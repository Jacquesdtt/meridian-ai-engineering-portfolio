# Technical Debt & Known Limitations

This document captures assumptions, trade-offs, and technical debt. It serves as a backlog for future refactoring and a transparency ledger for SREs and Product Leads.

## 1. Known Technical Debt
*   **Global Dependency Management:** (Sprint 0) Due to AppLocker restrictions, we are installing all `pip` packages to the global user scope instead of an isolated `.venv`. This risks package conflicts with other projects on the host machine. **Resolution Plan:** Partly paid down in Sprint 5 — `Dockerfile` + `docker-compose.yml` containerize the FastAPI service. Local AppLocker development still uses `py -3.13 -m …`, and the Azure Container Apps deploy (WS-2) is still open.
*   **Balance outliers in training CSV:** (Sprint 1) `start_balance` / `Running_Balance` extremes ±1e10 remain in `training_data.csv`. Trees tolerate; linear scaling would not. **Resolution Plan:** Handled as tree-native in Sprint 2; no change required for serve.
*   **Early-tenure Lag3 NaNs:** (Sprint 1) ~138,640 rows missing `Active_Txn_Lag3`. **Resolution Plan:** Native missing support in XGBoost (Sprint 2) — accepted. Side effect: `dtreeviz` fail-softs on these NaNs, so no surrogate tree diagram exists.
*   **Portable model vs MLflow DB:** (Sprint 3) Runtime loads `Models/ops/`; minting a new export still needs a one-time local `mlflow.db` with the ops run. **Resolution Plan:** Re-run `Code/Sprint3/export_ops_model.py` after any new ops training run; keep `Models/ops/` committed.
*   **MLflow store not reproducible from a clean clone:** (found 2026-09-15) `mlflow.db`, `mlartifacts/` and all `*.csv` data are gitignored, so on a fresh clone `export_ops_model.py` cannot find run `3f575754…` and exits. Serving still works because `Models/ops/` is committed. **Resolution Plan:** Back up the MLflow store somewhere durable, or rebuild it by running `Code/Sprint1/02_feature_engineering.ipynb` → `Code/Sprint2/01_modeling_and_rai.ipynb` → `Code/Sprint3/export_ops_model.py` (raw data must be obtained separately).
*   **Preprocessor not logged to MLflow:** (found 2026-09-15) The notebook logs only the booster (`mlflow.xgboost.log_model`); `export_ops_model.py` re-fits the one-hot encoder on the fit months, so the MLflow run alone cannot rebuild the served pipeline. The notebook also still uses the deprecated `artifact_path=` argument. **Resolution Plan:** On the next training run, log the preprocessor (or one pyfunc pipeline with a signature) and switch to `name="model"`.
*   **No flagged demo fixture:** ~~(Sprint 3)~~ **Resolved (Sprint 4 red-team):** `Docs/Sprint4/fixtures/{below_threshold,flagged}_demo.json` + Streamlit presets. Re-verify after ops re-export via `.agents/scratch/verify_s4_fixtures.py`.
*   **Demo RBAC ≠ production IdP:** (Sprint 5) ADR 007 role picker / `X-Demo-Role` is spoofable by design. **Resolution Plan:** Entra ID / real auth deferred to a production system (ADR 012, JR-OPEN-05).
*   **Draft gate enforced in two places (ADR 006):** (recorded 2026-09-17) Deliberate, documented debt taken on because AppLocker blocked Streamlit from calling FastAPI over `localhost`. `POST /drafts` re-scores from raw features and gates on the server, but the Streamlit UI imports `score_raw_features`, `create_draft` and `draft_store` and writes to SQLite directly. Interest paid meanwhile: (1) the score gate and role checks on the UI path are only as strong as the UI code and SQLite file permissions; (2) the rules exist twice and have started to diverge (the API path passes `extra_context` to the drafter, the UI path does not); (3) it led the Final Report to overstate "UI cannot bypass" (Corrections A8-p). Acceptable for a single-machine demo with trusted users. **Resolution Plan:** Before any multi-user or production use, make FastAPI the only component that can write drafts and turn Streamlit into an HTTP client (Corrections **F8**; follow-on to ADR 006 / ADR 008).
*   **Live Azure drafts:** ~~(Sprint 5) Local `.env` may lack `AZURE_OPENAI_ENDPOINT`.~~ **Resolved (2026-07-17; configuration refreshed 2026-09-24):** Azure live path was verified with `gpt-4o-mini` + `text-embedding-3-large`, then moved to configured chat deployment `gpt-5-mini` with `text-embedding-3-large`. Any machine without Azure configuration falls back to the stub drafter and BM25-only retrieval (`azure_configured=false`); the offline path remains DoD-complete.

## 2. Design Limitations
*   **Asynchronous Processing:** GenAI draft creation may block the FastAPI request when Azure is configured. Sprint 3 defaults to a **stub** drafter when Azure is absent; on Azure failure uses `stub_fallback`. **Future Improvement:** If live Azure latency exceeds 5 seconds, refactor to a task queue and return 202 Accepted.
*   **Approved ≠ Sent:** Friction-Gate has no outbound mail integration by design (ADR 003). Agents must send outside the system after Approve.
*   **ADR 006 vs cloud split:** ~~SQLite + in-process Streamlit assumes shared filesystem.~~ **Updated 2026-09-24:** since F8 the UI calls FastAPI over HTTP and only the API writes SQLite, so a separate Streamlit container would not share the database file. The API container is built and smoke-tested locally; Streamlit-in-cloud is still not deployed, so do not claim it (ADR 008 follow-on).

## 3. Core Assumptions
*   **Data Integrity:** We assume the `StartingFiles/` CSVs represent a statistically valid distribution of the total customer base and are not affected by survivorship bias.
*   **Corporate Policy:** We assume the current corporate proxy will not intercept or alter the SSL certificates required to communicate with the `azure.openai.com` endpoints. (If so, we will need to inject local root certs into the `httpx` client).
